## Authority rule

`TEBRA-DESIGN-SYSTEM.md` wins on **values** (hex, px, radii, tokens, prop names).
The PNGs win on **arrangement** — layout, proportion, adjacency, what a variant grid contains.
The SVGs are **verbatim**: paths get embedded as-is, never redrawn, never substituted, never
colour-normalised.

When a layer disagrees with another, the .md's value is the one to build, **and the disagreement is
reported as a finding**. It is never silently reconciled in either direction.

## Open — need Daniel

**24. Two values in the Autocomplete frame are not source-derivable.** Neither the .md nor the schema
gives the Autocomplete popper's **vertical offset** or the paper's **elevation**. The MUI checkout has
no `node_modules`, so neither could be read from source. The frame draws the offset flush (matching
the Menu) and mirrors the Menu's Elevation/8, and its caption says so in those words — but do not read
either value off that frame until it is checked against `@mui/material/Autocomplete`.

**25. The Autocomplete popup indicator's rotation is undocumented.** §3.4 proves the *Select* caret
never rotates, because `IconComponent` is a props-less arrow function that discards `ownerState`.
Autocomplete reaches the same `DownCaret` through `popupIcon` → `popupIndicator`, a **different code
path** — MUI rotates the indicator *button* by class, not the icon by ownerState, which would rotate
regardless of the props-dropping bug. The .md says nothing about it. The frame draws it unrotated and
asserts nothing. Worth one source check; if it does rotate, that is a genuine divergence between two
surfaces using the same glyph.

**26. The pagination item gap is not in either record.** Drawn at 6px on the basis of MUI's
`PaginationItem` `margin: 0 3px` per side. This is the one measurement in the three new frames taken
from memory of MUI rather than from a file, and it is flagged in the frame's own caption. Verify
before the kit is treated as authoritative for pagination spacing.

**28. The mis-build card was clipped in the card-header-band frame.** *(Found during certification.
My defect, introduced when I built the frame. **Fixed and verified on disk 2026-08-10.**)*

The frame is 820 wide with 40px padding, giving 740 of content. The two example cards are 360 each
with a 72 gap — **792, which is 52 over**. The frame clips, so the right-hand "WRONG — 68px" card
loses its right edge: it measures **348px wide instead of 360** and runs flush to the frame boundary
with no right margin and no rounded corner, where the left card has both. Measured: white spans
`x 80..799` (360px) and `x 944..1639` (348px, cut off).

For comparison, right margins across all eight frames: nav 40, Select 40.5, composed table 32,
Autocomplete 45.5, Pagination 40, **card header band 0**. Dialog-over-scrim and stacked-adjacency
also measure 0, but those are **full-bleed by design** — their own background fills the frame, so
there is no content to clip. The card header band is the only frame where a *foreground element*
runs off the edge.

**What this does and does not damage.** Both band heights still measure exactly right — 48 and 68 —
and both titles are fully legible, so the value the frame exists to teach is intact. What is wrong is
that a card in a certified ground-truth image is visibly truncated, and its **width reads 348 where
the card is 360**. An agent taking card geometry off this frame would be 12px short.

**The fix.** Frame widened 820 → 900, rather than shrinking the example gap. Padding 40 and example
gap 72 are the constants across the composed frames — Select and Autocomplete both use them — while
frame width is already the free variable (Select 820, Dialog 900, nav 1520). Dropping the gap to 20
would have made this the only frame with a different internal rhythm. The title and note were widened
to the new 820 content width so the text still fills it, as it does in every other frame. Nothing
else changed: cards, bands, captions and copy are untouched, and the `PNG @2x contentsOnly` export
setting survived the resize, so no re-arming was needed.

Content width went from 740 with a 52px overflow to 820 with 28px of slack. The frame is now
900 × 404 (it got shorter because the wider note wraps into fewer lines), exporting at 1800 × 808.

**Verified on disk** after the Reference-page re-export: the file is **1800 × 808** (900 × 404 at 1x),
both cards measure **360px** (`x 80..799` and `x 944..1663`), band heights **48 and 68** exactly,
right margin **40.5px** — the same as the Select frame. The right card renders its rounded corner.
File count held at 103; the other seven REFERENCE frames re-exported byte-identical in dimensions.

**Why it hid.** Figma reported card width 360 and band heights 48/68 throughout — all true of the
nodes, none true of the render, because the clip happens at the frame boundary. Only measuring the
exported PNG showed it. §6.5, "pixels over property readbacks", caught a defect in the very artefact
built to teach it.
