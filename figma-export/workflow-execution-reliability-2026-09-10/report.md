# Execution reliability after the Allergies recovery

Repository safeguards are now shared by every model/harness. This batch changes instructions and the local workflow gates; it makes no Figma changes.

## Findings and decisions

The Allergies failure was a combination of inaccurate planning, ineffective property edits, clipped controls, repeated broad searches, uncertain-write recovery and repeated operator handoffs. It was not a controlled model comparison. Prior network errors remain unexplained; no claim is made that a model switch fixes them.

The operator asked to enshrine the prevention measures in the repo. The canonical policy is `workflow/execution-policy.md`, routed through CLAUDE.md and AGENTS.md and embedded in the generated contract. `.github/copilot-instructions.md` is a short pointer for Copilot; the existing `.clinerules` pointer reaches the same policy through CLAUDE.md. There is no copied competing rule set or new plugin requirement.

The operator's “Looks good” accepts the Allergies comparison. That acceptance is recorded in this batch's new workflow record; the completed Allergies record remains immutable.

## What changes for the next builder

1. Verify the actual target, tools and distinct planned controls once. Save their native property definitions. The local checker rejects requested variants or property names absent from the saved definitions, including the specific nonexistent outlined Add variant.
2. Build visible milestones inside one approved batch. Check affected nodes after edits and inspect a screenshot at meaningful checkpoints. Full-page/ten-rule audits still happen at close; routine progress does not cause repeated full rediscovery.
3. Read back uncertain writes before retrying. Two failed attempts stop that operation until a materially different, evidence-supported approach is identified. Roughly five minutes without visible progress or a concrete finding triggers diagnosis, not another unbounded continuation.
4. Correct routine facts and the batch's own mistakes without repeated permission requests. Record moves/conversions before acting. New design choices, code/library divergence, ambiguous ownership and scope expansion still stop for the operator. Additive-only, risk ownership and final visual review are unchanged.
5. Carry mappings, verified IDs, renders, unresolved issues and one next action across model/harness changes in `execution.json`. Planning and execution can happen in one session. Speak plainly to the UX designer and keep implementation details in the report.

## Local enforcement

New `start-batch` runs use version 3 and require `execution.json` beside the report. `check-batch` validates readiness, including unresolved execution failures. `finish-batch` requires verified milestone renders and the final comparison. Historical version-2 runs retain their existing requirements; checkpoints are not fabricated retroactively.

The component snapshot contains actual component IDs/keys and native `componentPropertyDefinitions`; planned properties are validated against their names, variantOptions and basic value types. The checker verifies evidence files exist, PNG signatures, inspection declarations and milestone completion. It does not independently contact Figma, prove that evidence is current, or inspect pixels. Retry/time thresholds remain executor instructions, not an installed scheduler or harness interceptor.

New runs also fingerprint pre-existing unrelated dirty files. The finish gate permits those only while unchanged and still rejects new unrelated edits. This prevents pressure to hide, move or commit a user's unrelated file just to pass a batch gate. Existing runs without a baseline do not gain a retroactive exemption. The previous takeover's separate `.clinerules` commit is historical, not the recommended future workaround.

## Verification

- Execution regression tests cover readiness/resumption, wrong target/record, missing mappings/evidence, nonexistent variants, wrong property names/types, unresolved writes, incomplete/uninspected renders, non-PNG files, duplicate milestones, recovery and unrelated-file preservation.
- Existing workflow self-tests still cover risk/approval locks, allowlists and record isolation.
- Generated contract includes and freshness-checks the new canonical policy and Copilot routing pointer; policy projection content is checked as well as its digest.
- Workflow/store validation and whitespace checks pass. Canvas checks are not applicable: no Figma file was opened or mutated.

These changes reduce the opportunity for the observed failures and detect several at a local gate. They cannot guarantee that a model follows instructions, reports every retry or judges a screenshot correctly. The next clean, bounded build is still the practical test of a cheaper model with this workflow.
