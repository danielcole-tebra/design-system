Lean set = CLAUDE.md + contract + largest manifest item + current-state + largest of the latest record per workstream. It is a reported target rather than a hard stop: its largest component can be an immutable DONE record, and a hard stop there would block every later session with no repair. The component ceilings are the hard stops; each is repairable (regenerate, trim an IN PROGRESS record, move bulk to evidence) or, for a DONE record, reported for the next record to cite. The record's own `ceilings` block lists the values as adopted; this reporting mode for the lean set was settled after finalize and is stated here and on the validator line.

## Decisions for the operator

1. **Ceiling values.** Set by the executor as tooling parameters with 23 to 50 percent headroom over the largest current file (table above). Retuning is a catalog edit with a record.
2. **DONE records over the record ceiling** are reported, not failed, because they are immutable. The hard stop before a record becomes immutable needs either the store API (`finalizeRecord`) or the templated finalize helper planned for Batch D. Confirm it goes to Batch D, together with the schema self-test assertion fix.
3. **Carry-over from batch A.** The stopped Flowsheets batch (2026-09-11) still holds untracked files and uncommitted edits to flags/active.json and manifest.json; preserved, not committed. This commit's regenerated indexes and contract digest that working tree, so a fresh clone fails validation until those files are committed; the working tree validates.
