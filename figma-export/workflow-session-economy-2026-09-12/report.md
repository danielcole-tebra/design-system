## Rule 16, canonical text

One batch per session; bounded reads. A session holds one batch: it opens with the lean start, closes with that batch's finalize and commit, and the next batch starts a fresh session. A stopped batch resumes in a new session from its record and checkpoint; a session that already holds a finished batch does not open a second one. Startup reading is the lean set: the validator line, the generated contract, the selected manifest item, indexes/current-state.json and the last record it names. The contract's sources (workflow/rules.json, workflow/execution-policy.md, the canonical CLAUDE.md sections) and the workflow tooling (scripts/workflow, scripts/schema/lib.js, earlier apply and finalize scripts) are not read at startup: the contract is digest-checked, so the text it carries is current, and the record-store shape is stated in the rule so no earlier script is needed as a template. A tooling file is opened only when the validator fails, the tooling is the approved work, or the contract lacks something the batch needs, and that read is named in the report. Independent reads go in one call. A file is read once per session and by scoped projection, never whole when a part is needed; a persisted tool result is read for the range required. Every batch report states how many calls and how many result bytes preceded the first task action.
