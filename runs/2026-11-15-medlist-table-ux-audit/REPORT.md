# Comparison F: table UX audit

Evidence date: 2026-11-15. Scope: [Comparison F](https://www.figma.com/design/yh2F6OUgdI6K0risLtKLEQ?node-id=91-10443), screen `91:10446`, table `91:10496`, file `yh2F6OUgdI6K0risLtKLEQ`. Read-only audit; no design changes. This is a heuristic assessment, not provider validation, accessibility certification or a fresh shipping-code audit.

F has a coherent scan structure: stable columns, full medication names, aligned row actions, visible issue text and details under their associated headers. The most consequential unresolved question is whether the collapsed view withholds information needed for medication review. Reducing displayed text does not by itself demonstrate reduced cognitive or administrative burden.

## How the references apply

The AHRQ framework supports task-relevant information, overview plus accessible detail, proximity and reduced retrieval effort (printed pp. 8–10 and 19–20). It separately emphasizes knowing data provenance (p. 11). Its cognition heuristics warn against hiding frequently needed information (p. 52), and graphic guidance addresses legibility and keeping related controls together (p. 53). My interpretation is that disclosure should follow task relevance, not merely text length. These principles support the current alignment work while challenging our assumption that every source marker can be secondary. [AHRQ report](https://digital.ahrq.gov/sites/default/files/docs/citation/09-10-0091-1-EF.pdf).

[Carbon's table guidance](https://carbondesignsystem.com/components/data-table/usage/) supports supplementary information in expansion, selection with batch actions, visible sort states and sufficient table width. It also permits batch expansion where appropriate. These are useful patterns, not instructions to substitute Carbon styling or copy its exact dimensions into Tebra. [GOV.UK's table guidance](https://design-system.service.gov.uk/components/table/) reinforces the comparison/scanning purpose and semantic header relationships.

[MUI column dimensions](https://mui.com/x/react-data-grid/column-dimensions/) supports explicit minimums, flexible allocation and resizing. [MUI column definitions](https://mui.com/x/react-data-grid/column-definition/) separates display formatting from sorting/filtering values. These mechanisms can support F, but the specific widths and activity data contract remain our responsibility.

[MUI master-detail panels](https://mui.com/x/react-data-grid/master-detail/) are a Data Grid Pro capability with customizable content and height. Our per-column expansion is a custom composition: do not assume a stock detail panel automatically preserves every header alignment through column resizing, visibility or reordering. Verify that behavior in an implementation spike before claiming fidelity.

[MUI accessibility](https://mui.com/x/react-data-grid/accessibility/) documents meaningful row headers, density and custom-cell focus responsibilities. [WAI's grid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) distinguishes a managed keyboard grid from an HTML table and explains the extra complexity of multiple controls in a cell. Choose and test the appropriate behavior; visual table styling alone establishes neither.

## Recommended next experiment

Preserve F as the comparison baseline. First validate collapsed content with a small task study: identify a patient-reported medication; compare directions for two medications; find a send failure and act; distinguish selection from review; locate a medication off the first page; resume after an interruption. Measure correctness, missed information, unnecessary expansions/clicks and recovery, as well as time and perceived effort. Include providers and staff who perform the actual tasks.

Then test the smallest evidence-backed variation: keep pharmacy/prescribing detail disclosed, preserve medication identity, make necessary provenance apparent, and reduce repeated retrieval when comparing directions. A view exposing directions across rows is a hypothesis to test, not an approved new feature. No generic table guideline can settle which clinical information is secondary for this workflow.
